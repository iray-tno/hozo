# Vite runtime candidate facts against the final module graph

Stacked on #1292, source `47acc2f1e9fb966beac5bae5548f21feabfd21b3`.
This is the first adapter consumer of the shared native-fact reconciler,
not a final production ordering context or a candidate stylesheet replacement.

## Boundary

Vite build mode captures an opaque `CandidateCache.exportFile` record
immediately after the existing native scan, before an await can change the
shared physical-file entry. Metadata contains one module ID, environment,
input hash, producer identity and native record, not the project namespace.
Pass-through modules return metadata only, preserving existing code/maps.

The supported `moduleParsed` hook seals fresh observations against the code
after downstream transforms, including Vite's OXC JSX conversion. At `buildEnd`,
`getModuleIds`/`getModuleInfo` supply the independent final ID/code/metadata set.
A fresh producer can seal only its unmodified observation once; replay must
already match the final code. It cannot bless changed code by resealing a
cached receipt. Native import still validates schema/scan version/source policy.
These hashes bind scan facts to a bundler artifact, not its eventual rendered
behavior, theme/order namespace, or classes generated by later plugins.

The configured source walk remains separate from reachable modules. Unimported
configured content stays in the denominator; a second discovery/content check
detects authored additions, deletions and changes during the build. Initial
authored facts use the existing policy-and-mtime native cache. Hashing the source
does **not** independently prove a warm native entry was scanned from those
bytes: deliberately preserved mtimes remain outside this cache's guarantee.
This is recorded in `authoredValidation`, not described as a cryptographic cache.

Only observations whose full IDs remain in the final graph contribute derived
facts. An absent MDX module cannot survive through an old physical cache entry.
A query module not currently scanned by the adapter has no receipt and records
incomplete status; the physical file's facts are not copied to it. Virtual or
otherwise ineligible modules are outside the existing Hozo transform boundary,
not newly supported by this inventory.

The internal `node_modules/.hozo/candidate-inventory-<environment>.json` records
`scope: runtime-source-facts` and `finalOrderingReady: false`. Incomplete data has
no candidate union, even if other inputs were accepted. Build start replaces old
evidence with `collecting`; graph failure writes `failed`. A complete graph
inventory is not a successful bundle/render certificate. No inventory is emitted
as an application asset and no public option was added. Dev mode remains unchanged.

## Measured

Local Windows, CPU affinity 1, Idle priority, serial test execution:

- `pnpm --filter @hozo/vite build`: passed.
- `pnpm --filter @hozo/vite exec node --test --test-concurrency=1 src/*.test.ts`:
  **51 passed**, including **12 new tests**.
- `pnpm lint`: 1,697 files passed. `pnpm docs:check`: 76 primitives,
  repository layout and 24 package README footers passed.
- Six new small real-build tests exercise the supported Vite/Rolldown hooks:
  transformed MDX and unimported authored files; downstream code; real lowered
  JSX after OXC without static classes leaking into runtime candidates; missing
  query receipts; removed graph/authored inputs across builds; mid-build authored
  changes/additions; and failed builds replacing previous complete evidence.
  There are six test cases with some cases performing two successive builds.
- Other new controls cover JSON receipt replay with scanning/persistence
  forbidden, changed/foreign/missing receipts with no partial union, environment
  and trusted-source policy mismatch, producer mutation/resealing, authored
  staleness, and bounded per-module metadata independent of authored file count.
- Existing dev, epoch cancellation, namespace expansion, MDX and policy tests
  remain green. No utility, conformance denominator or emitted winner changed.

Initial harness failures were retained in the execution record: a virtual-entry
probe did not resolve, Node strip-only mode refused a parameter property, and
the temporary library fixture needed an explicit CSS output filename once it
started emitting CSS. The harness/setup was corrected, not production refusal
policy or test expectations weakened.

## Still open

JSON round-trip replay proves the receipt protocol; it is **not** evidence that
Vite 8 reused a cached transform in a real watch build. Its documented
`shouldTransformCachedModule` compatibility hook is a no-op and is not used.
Multi-environment/SSR cache lifecycle, plugins producing new Hozo input after our
pass, and unsupported virtual modules require their own evidence.

The reconciled union does not yet drive candidate CSS. Existing cache/CSS
publication is not pruned or replaced by this file. Query-module observations,
static/actual compiler units, one final ordering namespace, re-emission and
cross-worker publishing coordination remain before shared winners can turn on.
Next and Metro do not acquire a final graph contract through this Vite change.

Build-only work adds content hashing/final discovery and native record replay;
it does not add a parser per reconciled file or a project-sized context to each
metadata entry. No speed, heap, package-size, full application build, device
pixel, AT, or new coverage-percentage claim was measured here. The root JS/pack
suite and heavy application builds are left to CI under the user's local CPU
restriction; Rust/compiler sources are unchanged in this layer.
