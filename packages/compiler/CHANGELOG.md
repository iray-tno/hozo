# @hozo/compiler

## 0.5.0

### Minor Changes

- [#1869](https://github.com/iray-tno/hozo/pull/1869) [`2f386b3`](https://github.com/iray-tno/hozo/commit/2f386b331c1138559f6853f5914d6e17d0906a41) Thanks [@iray-tno](https://github.com/iray-tno)! - Compile known, supported `tailwind-merge` inputs (`twMerge` / `twJoin` and merger helpers like `cn(...inputs) => twMerge(clsx(inputs))`) at build time. When all possible class tokens are known and supported, including conditional inputs such as `cn('px-3', active && 'px-2')`, Hozo resolves utility conflicts using `twMerge`'s class-group trie and conflict table without calling `twMerge` at runtime. Opaque caller class lists keep the complete original call so custom tokens, arbitrary values, and nested conflicts retain their exact semantics. Native resolves the resulting classes through the project candidate map and applies supported variants using state from the host. Opaque `twJoin` arguments and its wrappers also stay at runtime to preserve array flattening. Helpers that call `extendTailwindMerge` or `createTailwindMerge` stay at runtime.

- [#1932](https://github.com/iray-tno/hozo/pull/1932) [`ddefc28`](https://github.com/iray-tno/hozo/commit/ddefc28020ed6d25723a811660c663e54081c02e) Thanks [@iray-tno](https://github.com/iray-tno)! - `@hozo/compiler/format-jsx` exports `formatJsx`, which lays out compiled JSX one element per line for a person to read. The compiler's own output stays on one line, so source positions hold. `hozo show` now prints its JSX through it, laid out the same way as the REPL's panes.

- [#1919](https://github.com/iray-tno/hozo/pull/1919) [`9d20975`](https://github.com/iray-tno/hozo/commit/9d20975684383ed659085fc48dad34f70294505e) Thanks [@iray-tno](https://github.com/iray-tno)! - Add `hozo manifest` and `hozo links` to `@hozo/cli`. They run the same commands as `hozo-manifest` and `hozo-links`. Both old binaries keep working for one minor release and print a deprecation line on stderr.
  
  Both now use the `hozo` exit codes: `1` for a stale file under `--check`, and `2` for a command that could not run. A `2` ends its stderr line with a string code such as `[config-not-found]`. `hozo-links` used to exit `1` for configuration errors. `hozo-manifest` used to ignore unknown options and crash on a package it could not read.
  
  `hozo-links` now also runs when npm links it into `node_modules/.bin` as a symlink. Before, the linked binary did nothing and exited `0`.
  
  `@hozo/navigation` is an optional peer of `@hozo/cli`. Without it, `hozo links` exits `2` with `[missing-package]`.

- [#1927](https://github.com/iray-tno/hozo/pull/1927) [`9dff278`](https://github.com/iray-tno/hozo/commit/9dff278a4cf197716791f7c2530ae188789866f9) Thanks [@iray-tno](https://github.com/iray-tno)! - Add `hozo explain [CODE]`. It shows what a diagnostic means, a source that raises it, and the compiler's message for that source. Without a code, it lists every code. It accepts `aria-name-prohibited` as well as `ARIA_NAME_PROHIBITED`, and suggests close matches for an unknown code. `--format json` prints the entry.
  
  `@hozo/compiler` now ships `diagnostics.json`, the catalog `explain` reads. The catalog is generated from the compiler's own documentation of each code and from the conformance cases. `explain` reads only this file, so it compiles nothing and loads no native addon.

- [#1946](https://github.com/iray-tno/hozo/pull/1946) [`225688d`](https://github.com/iray-tno/hozo/commit/225688dada614b75f9527f48e02c3d014681c586) Thanks [@iray-tno](https://github.com/iray-tno)! - `hozo show` now gives two more routes a class list can take:
  
  - **owner-callback**: on Native, the list is compiled into a callback that its pattern owner, such as a Chip or a Menu's items, applies with its own state.
  - **component**: the list is handed to a component the compiler does not lower, such as `@hozo/ui`'s `Button`, which resolves it. Before, such a list was not reported at all.
  
  Both come from new compiler evidence:
  
  - On Native, `tailwindPlan` now includes `ownerCallbacks` when there are any.
  - A compiler gains `componentClassLists(source)`, read from the same parse `compileNative` lowers.

- [#1953](https://github.com/iray-tno/hozo/pull/1953) [`be6ec5f`](https://github.com/iray-tno/hozo/commit/be6ec5f24f5fbf8002f9c5d25e9ac3de1bdfbedf) Thanks [@iray-tno](https://github.com/iray-tno)! - `hozo show` now says when a Pressable, Link or TextInput resolves a class list it cannot read with its own state on Native, as it already did for a pattern owner. It also lists an unread secondary class list such as a Menu's `itemClassName={cls}` with `--web`, under its own prop.
  
  From the compiler:
  
  - On Native, `tailwindPlan` includes `runtimeStates` when there are any.
  - The Web now warns `DYNAMIC_CLASS_NAME_NOT_RESOLVED` for an unread secondary class list, as it does for `className`.
  - On both backends, that warning points at the list's attribute rather than its element.

- [#1831](https://github.com/iray-tno/hozo/pull/1831) [`5217533`](https://github.com/iray-tno/hozo/commit/5217533abc7ec212bc2a99f2a191f8b741085d19) Thanks [@iray-tno](https://github.com/iray-tno)! - Tailwind's class order is now the default for every compile, not only where a project's CSS is captured.
