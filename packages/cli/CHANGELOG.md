- [#1906](https://github.com/iray-tno/hozo/pull/1906) [`5f09276`](https://github.com/iray-tno/hozo/commit/5f09276ca888a122d38469a930d0f1f60ab759ae) Thanks [@iray-tno](https://github.com/iray-tno)! - Add `@hozo/cli`, the `hozo` command. `hozo dry-fit` (alias `migration-audit`) runs the migration audit with the same options and the same stdout and JSON. `hozo-migration-audit` keeps working for one minor release and prints a deprecation line on stderr.
  
  Exit codes are now `0` passed, `1` findings at or above `--fail-on`, `2` the command could not run. An input error (an unknown option, a missing checkout, an unreadable baseline) used to exit `1`, the same as a finding; it now exits `2` and ends its stderr line with a string code such as `[unknown-option]`.

- [#1919](https://github.com/iray-tno/hozo/pull/1919) [`9d20975`](https://github.com/iray-tno/hozo/commit/9d20975684383ed659085fc48dad34f70294505e) Thanks [@iray-tno](https://github.com/iray-tno)! - Add `hozo manifest` and `hozo links` to `@hozo/cli`. They run the same commands as `hozo-manifest` and `hozo-links`. Both old binaries keep working for one minor release and print a deprecation line on stderr.
  
  Both now use the `hozo` exit codes: `1` for a stale file under `--check`, and `2` for a command that could not run. A `2` ends its stderr line with a string code such as `[config-not-found]`. `hozo-links` used to exit `1` for configuration errors. `hozo-manifest` used to ignore unknown options and crash on a package it could not read.
  
  `hozo-links` now also runs when npm links it into `node_modules/.bin` as a symlink. Before, the linked binary did nothing and exited `0`.
  
  `@hozo/navigation` is an optional peer of `@hozo/cli`. Without it, `hozo links` exits `2` with `[missing-package]`.

- [#1927](https://github.com/iray-tno/hozo/pull/1927) [`9dff278`](https://github.com/iray-tno/hozo/commit/9dff278a4cf197716791f7c2530ae188789866f9) Thanks [@iray-tno](https://github.com/iray-tno)! - Add `hozo explain [CODE]`.   `@hozo/compiler` now ships `diagnostics.json`, the catalog `explain` reads. The catalog is generated from the compiler's own documentation of each code and from the conformance cases. `explain` reads only this file, so it compiles nothing and loads no native addon.

- [#1939](https://github.com/iray-tno/hozo/pull/1939) [`8947a3a`](https://github.com/iray-tno/hozo/commit/8947a3ab05048e54374a9394f88c7d42ca0b6d0d) Thanks [@iray-tno](https://github.com/iray-tno)! - `hozo show` now reports each class list in the file. - [#2069](https://github.com/iray-tno/hozo/pull/2069) [`5e28d95`](https://github.com/iray-tno/hozo/commit/5e28d95f6ab0ebf47af8fa94b26a012262a8fb6f) Thanks [@iray-tno](https://github.com/iray-tno)! - A class expression the compiler cannot read now says which kind it is. Before, all three kinds got `DYNAMIC_CLASS_NAME_NOT_RESOLVED`:
  
  - `CLASS_NAME_PASSED_THROUGH` is a class prop passed on unchanged, such as `className={className}`. Its classes compile where the caller writes them.
  - `CLASS_NAME_ASSEMBLED` is a class name built from pieces, such as `` `bg-${color}-500` `` or `'p-' + size`. It has a rule only when the whole name is written literally somewhere in the project.
  - `DYNAMIC_CLASS_NAME_NOT_RESOLVED` remains for any other value the build cannot enumerate.
  
  If you suppressed `DYNAMIC_CLASS_NAME_NOT_RESOLVED`, the first two now arrive under their own codes. `hozo show` treats all three as classes resolved at run time.

- [#2009](https://github.com/iray-tno/hozo/pull/2009) [`2732f4a`](https://github.com/iray-tno/hozo/commit/2732f4a1578170f982304a2c4a7c84a3f4a5891c) Thanks [@iray-tno](https://github.com/iray-tno)! - `hozo square` checks that every theme token an `@hozo/ui` component names (`bg-hozo-accent` names `hozo-accent`) is defined by the theme the project's stylesheet resolves. It checks both components copied by `hozo add` and installed ones the project imports. An undefined token is an error: its classes compile to nothing, though no file in the project changed. This happens when upstream renames a token a copy still uses, or when a copied theme is older than a component. It also reports each copy that `@hozo/ui` has moved on from, with the `hozo add --diff` and `--update` to run, as a new `info` severity that never fails.
