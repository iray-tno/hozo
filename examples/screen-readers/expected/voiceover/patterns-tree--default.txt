#   "role=tree and role=treeitem are announced as 'table' and 'listbox'"

# It reports the Authoring Practices tree example itself being conveyed as a
# table with "list boxes" for treeitems, and names the cause: AXTable where
# AXOutline was wanted, "an artifact of AppKit trees being implemented as
# single column tables". Filed out of w3c/aria#1311.
#
# fixtures/tree-shape.html says the same thing from here. The Authoring
# Practices shape -- a branch owning its children in a role="group" -- and
# ours, flat rows carrying aria-level, on one page: VoiceOver called both
# "table Row 4 of 12 selected". In the nested one role="tree" has two DOM
# children and it still said twelve, so it is flattening the tree to count
# rows rather than reading our structure back.
#
# Approved, then, for something no markup here can change -- and the
# condition for unapproving it is written down rather than left to memory.
# If 215698 is fixed, VoiceOver will say something else and this line will
# start failing. That failure is the notification. Read the bug before
# loosening it.
